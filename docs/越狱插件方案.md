# Trae iOS 端分析与越狱插件方案

> 分析对象：`TRAE_Decrypted.ipa`（App Store 下载后砸壳）
> 目的：登录 iPhone 端后，自动拿到 relay「手动填写凭证」所需的
> `token / refreshToken / userId / clientId`。

---

## 1. 静态分析结论

### 1.1 基本信息

| 项 | 值 |
|---|---|
| Bundle ID | **`com.stone.solo.cn`** |
| 版本 | 0.0.21（build 0.0.21.6） |
| 最低系统 | iOS 16.6 |
| 编译 SDK | iphoneos 26.0 |
| 架构 | arm64 |
| 主二进制 | `TRAE`，约 164 MB（已解密） |
| 技术栈 | **Compose Multiplatform**（Kotlin）+ WKWebView 互操作 |
| 内置 SDK | 字节系：Heimdallr（APM）、BDTuring（验证码/风控）、RangersAppLog、TTAccount（账号）、DYOpenAuth |

判断依据：`compose-resources/` 目录、`SL*` 类名前缀、`com.multiplatform.webview.*`、
`ComposeUIViewController` 相关符号；没有 Flutter，也没有 RN bundle。

### 1.2 凭据相关的关键字符串

| 字符串 | 含义 |
|---|---|
| `cloudidejwt` / `cloudidejwtauthorization` / `cloudidetoken` | 凭据所在的 key/字段名 |
| **`X-Cloudide-Token`** | 请求头，模型调用携带的 token |
| `/cloudide/api/v3/trae/GetThirdPartyToken` | 取第三方 token |
| `/cloudide/api/v3/trae/SetThirdPartyToken` | 写入 token |
| `/cloudide/api/v3/trae/DisconnectThirdPartyToken` | 解绑 |
| `/api/remote/v1/auth/session/` | 会话鉴权 |
| `SLThirdPartyToken*`、`SLIssueSessionTokenRequest`、`SLSessionTokenData` | token 模型 |
| `SLInternalTraeGetRefreshTokenRequest`、`SLEnterpriseExchangeTokenRequest` | 刷新/兑换 token |
| `TTInstallKeyChainService`、`ttKeyChainService`、`EAccountKeyChainKey`、`com.toutiao.account.*` | 字节账号 SDK 的 Keychain 服务名 |

### 1.3 凭据在哪、怎么发

综合符号与接口路径，可以确定：

1. 登录由**字节账号 SDK（TTAccount）**完成，会话落 **Keychain**（服务名 `TTInstallKeyChainService` / `ttKeyChainService`）；
2. 业务层拿到会话后，向 `api.trae.cn` 发请求，凭据放在 **`X-Cloudide-Token`** 头（部分接口用 `Authorization`）；
3. `refreshToken` 在 `/api/remote/v1/auth/session/` 或 token 接口的 **JSON 响应体** 里；
4. JWT payload 的 `data.id` 就是 `userId`。

**所以最稳的注入点是网络层**，而不是去解 Keychain 里的字节 SDK 结构：

```
NSURLSession / NSMutableURLRequest  ──►  抓 X-Cloudide-Token / Authorization
NSURLSession completion             ──►  抓响应体里的 RefreshToken / Token / UserID
```

好处：Ktor（Darwin engine）最终走 NSURLSession，TLS 证书固定也不影响——我们在明文层。

## 2. 插件设计

### 2.1 Hook 点

| Hook | 作用 |
|---|---|
| `-[NSURLSession dataTaskWithRequest:completionHandler:]` | 记录请求头；包装 completion 解析响应体 |
| `-[NSMutableURLRequest setValue:forHTTPHeaderField:]` | 兜底：某些请求在 task 创建后才设置头 |
| `SecItemAdd` | 观察字节 SDK 写入 Keychain 的服务名（仅日志，不取值） |

只处理 host 含 `trae.cn` / `trae-api-cn` / `mchost.guru` 的请求。

### 2.2 提取逻辑

1. 从 `Authorization: Cloud-IDE-JWT <jwt>` 或 `X-Cloudide-Token` 取 JWT；
2. base64url 解 payload，取 `data.id` → `userId`；
3. 对 URL 含 `token / auth / login / session` 的响应，递归找
   `RefreshToken` / `refresh_token` / `Token` / `UserID` / `ClientID`；
4. 去重后输出。

### 2.3 输出

| 方式 | 说明 |
|---|---|
| 剪贴板 | 自动复制一段 JSON，直接粘进 relay 控制台「手动填写凭证」 |
| 落盘 | 写入 App 沙盒 `Documents/trae-creds.json`，Filza 可取 |
| 弹窗 | 显示 `userId`，确认已捕获 |
| 上报（可选） | 设置 `kRelayBaseURL` 后自动 `POST /api/web-auth` 入池 |

### 2.4 兼容性

- 越狱：Relaxin / Dopamine / palera1n 均可；rootless 走 `/var/jB`；
- 注入：MobileSubstrate / ElleKit；
- App 更新后若类名或端点变化，只需调整 `TraeHost()` 与响应匹配关键字。

## 3. 构建

### 3.1 准备

```bash
export THEOS=~/theos
git clone --recursive https://github.com/theos/theos.git $THEOS
# macOS 还需 Xcode 命令行工具；Linux/WSL 需 clang + ldid
```

### 3.2 编译

```bash
cd ios-tweak/TraeCreds
make package
# 产物：packages/com.yourname.traecreds_0.1.0_iphoneos-arm64.deb
```

### 3.3 安装

```bash
scp packages/*.deb root@<iphone-ip>:/var/mobile/Documents/
ssh root@<iphone-ip>
dpkg -i /var/mobile/Documents/*.deb
killall -9 TRAE   # 或 sbreload
```

或用 Sileo/Zebra 直接装 deb。安装后打开 App 登录，凭据会自动复制。

### 3.4 关闭 / 卸载

```bash
dpkg -r com.yourname.traecreds
```

## 4. 验证清单

1. 装好后打开 App，登录；
2. 观察是否弹出「Trae 凭据已捕获」；
3. 检查 `Documents/trae-creds.json` 是否存在；
4. 把剪贴板内容贴进控制台手动表单，点「添加账号」；
5. 控制台「账号与签到」出现新账号，`/v1/models` 可用。

---

## 5. 已知限制

- App 只在**登录后首次业务请求**时才带 token，纯粹打开 App 不会触发；
- 若账号走 WebView 内嵌登录，token 可能只在 WKWebView 的 localStorage 里，
  此时需要额外 hook `WKWebView`（当前版本未实现，可按需扩展）；
- `refreshToken` 依赖响应体解析，接口改版会失效；
- 越狱环境下 App 可能检测注入（BDTuring），出现闪退就把插件设为仅调试时启用。

---

## 6. 风险

- 插件只应安装在你自己的设备、登录你自己的账号；
- 不要分发编译产物——它具备导出任意登录态的能力；
- 抓到的 token 等同账号密码，剪贴板是全局的，用完清空；
- 多账号自动化本身违反 Trae 服务条款，封号风险自负。
