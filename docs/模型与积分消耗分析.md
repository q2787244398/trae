# 模型清单与积分消耗分析

> 基于 Trae CN Relay 实际部署环境实测整理。结论适用于 CN 版（edition=cn），上游为 api.trae.com.cn。
>
> 说明：本文档的"积分消耗"为**实测推导**（单请求扣分 ÷ token 量），非官方定价表。Trae 官方未公开各模型的精确费率，因此按档位给出相对参考。

---

## 一、模型总量

`/v1/models` 返回 **20 条记录**，去掉大小写别名后是 **17 个真实模型** + 1 个 `auto` 自动路由兜底。

模型名存在**大小写别名**（如 `DeepSeek-V4-Pro-Official` 与 `deepseek-v4-pro-official` 是同一个模型），调用时任选其一即可。

## 三、积分消耗的实测规律

### 规律 1：输入 token 是积分大头

实测单请求（DeepSeek-V4-Pro）：

| 场景 | 输入 tokens | 输出 tokens | 消耗积分 |
|---|---|---|---|
| 未命中缓存 | 28149 | 946 | **13.35** |
| 命中缓存 | 27482 | 375 | **1.32** |

**同一次请求，缓存命中与否相差 10 倍。** 大上下文 Agent 任务（如整仓库分析）每轮都要重发全部上下文，是烧积分的主因。

### 规律 2：Pro 级与Flash 级差3~10 倍

同为 deepseek 系列，Flash 级是 Pro 级的 1/5 ~ 1/3。大型 Agent 任务优先用 Flash/Turbo，只在关键决策步用 Pro。

### 规律 3：多账号池可显著提升可用量

每个 Trae 账号有独立额度（实测 600~5200 不等），配合 relay 的账号轮询（`/api/polling`）可把可用积分叠加。

**轮询的两种模式**（`GET /api/polling`）：

| 模式 | 行为 | 适用 |
|---|---|---|
| `round-robin` | 按顺序轮换账号，均摊消耗 | 账号额度接近时 |
| `credit-priority` | 按剩余积分从高到低排序，积分多的优先 | 账号额度差异大（推荐）|

配合 `model_enabled=false` 可把耗尽的账号移出候选池。

### 规律 4：账号耗尽会返回 4008

积分用尽时 Trae 返回业务码 **4008**（`Your requests have exceeded the quota`）。开启轮询后relay 会自动换号重试（最多 2 次）。

## 四、常见错误码对照

| 错误码 | 含义 | 原因与处理 |
|---|---|---|
| **4008** | exceeded the quota | 账号积分耗尽。开轮询自动换号，或手动关闭耗尽账号 |
| **4010** | access denied | 会话失效或风控。网页授权账号无 refresh_token 无法自愈，需重新授权 |
| **4011** | 账号级限流 | Trae 侧限流，稍后重试 |

## 五、账号授权的两种通路

源码见 `src/main.py` 的 `/authorize` 与 `/api/web-auth`。

| 通路 | 回调位置 | 适用场景 |
|---|---|---|
| **A** | 服务器 `/authorize` | 回调能直达服务器时 |
| **B** | 客户端 `127.0.0.1:8765`（web_login.py） | **Trae 强制要求回调 127.0.0.1**，绝大多数情况走这条 |

> 源码注释原文：
> `// Trae 授权页强制要求回调为 http://127.0.0.1:<port>/authorize，因此必须由本机 web_login.py 监听并转发凭据到服务器。`

**结论**：`web_login.py` 必须运行在**执行授权操作的那台设备**上。在手机上授权就要在手机上跑（iSH / 授权助手），无法转移到服务器。

### token 有效期与自动续期

relay 内置自动刷新（`auth.py` 的 `needs_refresh` / `refresh_account`）：

- 主动刷新：到期前 30 分钟自动调用 `ExchangeToken`
- 被动恢复：接口返回 401 / 业务码 1001 时自动刷新重试

**前提：账号必须存有 `refresh_token`。** 网页授权登录的账号只有 access token，令牌失效后无法自愈（表现为 4010）；IDE 授权登录的账号带 refresh_token，可自动续期。

## 六、实用建议

1. **大型Agent 任务用 Flash/Turbo**，关键步骤再切Pro；
2. **保持同一会话连续对话**以命中缓存（省 90% 积分）；
3. **启用 `credit-priority` 轮询** + 及时关闭耗尽账号；
4. **主力账号用 IDE 授权登录**，保留 refresh_token 以便自动续期；
5. **避开整仓库反复重发**——缩小上下文范围比换模型更省。
