# 安装与多账号使用说明

面向从零开始的部署。Windows 10/11，约 15 分钟。

---

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| Python | 3.11 及以上（3.13 / 3.14 亦可） |
| 网络 | 能访问 `trae-api-cn.mchost.guru`、`api.trae.cn`、PyPI 镜像 |
| 账号 | 一个能正常使用 Trae 的账号（多账号见第 5 节） |
| 端口 | 8000（relay）、8765（授权助手） |

> 没有 Python 的话去 python.org 装 3.12，安装时勾选 **Add python.exe to PATH**。
> 如果你机器上有便携版 Python（例如某些软件自带的 `python.exe`），也可以直接指定。

---

## 2. 安装

### 2.1 取代码

把本仓库下载到任意目录，例如 `D:\trae-relay`。目录结构保持不变（`relay/`、`scripts/` 同级）。

### 2.2 装依赖

```powershell
cd D:\trae-relay\scripts
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

脚本会：

1. 找一个可用的 Python（`python` / `py -3` / 常见安装路径）；
2. 在仓库根目录建 `relay-deps\` 并安装 `relay/requirements.txt`；
3. 生成 `.env`（如果不存在）。

### 2.3 配置 `.env`

用记事本打开 `relay\.env`（没有就复制 `relay\.env.example`），最少改这四项：

```ini
TRAE_AUTH_SOURCE=auto          # auto=读本机客户端；web-login=网页授权；manual=手动 token
UPSTREAM_MODE=ide              # 推荐 ide（最省积分），需要 1M 上下文才用 remote
HOST=127.0.0.1                 # 只监听本机
RELAY_API_KEYS=sk-local-换成你自己的随机串
```

可选（强烈建议，公网访问时必须有）：

```ini
RELAY_ADMIN_USER=admin
RELAY_ADMIN_PASSWORD=换成强密码
```

> 设置了 `RELAY_ADMIN_USER/PASSWORD` 后，`/api/*`、`/web/*`、`/v1/status` 需要 HTTP Basic 认证；
> `/v1/chat/*` 仍然只认 Bearer key。

### 2.4 启动

双击 `scripts\start-all.bat`，或：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-all.ps1
```

它会拉起 relay、Cloudflare 临时隧道（可选）、授权助手，并把公网地址写到桌面 `trae-relay-url.txt`。

控制台：`http://127.0.0.1:8000/web/login`（用户名密码见 `.env`）。

> 不想开公网隧道就加 `-NoTunnel`：`.\start-all.ps1 -NoTunnel`。

### 2.5 固定公网地址（Tailscale Funnel，推荐）

默认用 Cloudflare 临时隧道，地址每次启动都会变。想要固定地址：

```powershell
# 1) 安装 Tailscale 并登录（首次会给出授权链接）
tailscale up --hostname=trae-relay

# 2) 首次开启 Funnel 需要在后台点一次开关，命令会给出链接
tailscale funnel --bg 8000
```

得到固定地址：

```
https://trae-relay.<你的 tailnet>.ts.net
```

之后 `start-all.ps1` 会自动优先使用 Funnel（检测到 `tailscale funnel status`
里有 `*.ts.net` 就不再启动 cloudflared），控制台、API、iSH 授权命令全部可以写死这个地址。

管理命令：

```powershell
tailscale funnel status            # 查看映射
tailscale funnel --https=443 off   # 关闭
```

> Funnel 是公网可达的，必须配置 `RELAY_ADMIN_USER/PASSWORD`；`/api/*` 的 Basic 认证
> 是唯一防线。

## 3. 首次登录（拿到第一个账号）

三种方式，任选：

### A. 本机 Trae 客户端（最省事，推荐）

1. 在 PC 上打开 **Trae CN 客户端**并登录；
2. `.env` 设 `TRAE_AUTH_SOURCE=auto`；
3. 重启 relay。

relay 会解密 `%APPDATA%\Trae CN\User\globalStorage\storage.json` 里的登录态，不需要网页授权，也没有频率限制。

### B. 网页授权

1. 控制台 → 账号与签到 → 「使用 Trae 网页授权登录」；
2. 本机需运行授权助手（`start-all.bat` 已自动启动，监听 8765）；
3. 浏览器登录 Trae → 授权 → 凭据自动写入。

> 手机端授权：先用 iSH 跑 `web_login.py`，再从 `http://127.0.0.1:8765` 发起。
> **不要反复点击**，上游登录接口有频率风控（"X-访问太频繁"），触发后要等 30–60 分钟。

### C. 手动填 token

控制台 → 「手动填写凭证添加账号」：

| 字段 | 来源 |
|---|---|
| Token（Cloud-IDE-JWT） | 客户端 storage.json（`scripts\dump-token.ps1` 可导出）/ 浏览器 F12 请求头 / iOS 插件 |
| Refresh Token | 登录接口响应的 `RefreshToken` 字段（可选） |
| User ID | JWT payload 里的 `data.id`（可选） |
| Client ID | 默认 `ono9krqynydwx5` |

## 4. 客户端接入

### DeepSeek Harness

设置 → 模型 → 添加模型提供商 → **自定义模型 API**：

| 字段 | 值 |
|---|---|
| Provider ID | `trae-relay` |
| API 协议 | OpenAI Chat Completions |
| API 地址 | `http://127.0.0.1:8000/v1` |
| API 密钥 | `RELAY_API_KEYS` 里的值 |
| 模型 ID | `deepseek-v4-flash`（或 `/v1/models` 里的任意 id） |

### Codex

```toml
model_provider = "trae-relay"
model = "deepseek-v4-flash"

[model_providers.trae-relay]
base_url = "http://127.0.0.1:8000/v1"
wire_api = "chat"
```

### Claude Code

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:8000
export ANTHROPIC_API_KEY=<RELAY_API_KEYS>
export ANTHROPIC_MODEL=deepseek-v4-flash
```

### 任意 OpenAI SDK

`base_url = "http://127.0.0.1:8000/v1"`，`api_key = <RELAY_API_KEYS>`。

## 5. 多账号

### 5.1 添加账号

- 网页授权：控制台点「授权登录」，每个账号登录一次；
- 手动：把另一个账号的 token 粘进手动表单；
- iOS：装插件后在手机上登录，自动复制凭据（见 `docs/越狱插件方案.md`）。

添加后账号出现在「账号与签到」列表，默认启用。

### 5.2 启用 / 停用

- 每个账号有独立的「模型请求」开关：关闭后不接收新请求，但签到、状态刷新照常；
- 全部关闭时，聊天接口返回 `503 model_account_unavailable`，不会偷偷绕回管理账号。

### 5.3 轮询

控制台「轮询与设置」：

| 模式 | 行为 |
|---|---|
| 关闭 | 只用当前选中账号 |
| 顺序轮询 | 每个新会话轮换到下一个启用账号 |
| 积分优先 | 优先用积分多的账号 |

每账号默认 2 个并发槽位（`TRAE_WEB_PARALLEL_LIMIT`），满了排队，超时返回错误。

### 5.4 切换

列表里点「切换」即把某账号设为当前默认（管理用）；轮询开启时新请求仍按轮询选号。

### 5.5 会话粘性

同一个会话（`session_id` 或历史指纹相同）会**粘住**首次使用的账号和 JWT，避免并发切号串账；
会话空闲 1 小时后释放。

### 5.6 签到

- 单账号：列表里点「签到」；
- 全部：点「一键轮询签到」；
- 定时：开启「自动签到」，设定北京时间，relay 到点自动跑；
- 遇到 `9074` 风控码会自动换设备 ID 并退避重试。

> 签到和多账号都属于规避服务条款的行为，账号风险自负。

### 5.7 账号模型开关与签到互不影响

关闭「模型请求」的账号仍会参与签到、积分查询和状态刷新，这是刻意设计。

## 6. 端点与成本

| 端点 | 单次固定开销 | 工具调用 | 适用 |
|---|---|---|---|
| `ide` | ~100 tokens | 原生 tools | 默认推荐 |
| `solo` | ~100 tokens | 原生 tools | ide 异常时 |
| `remote` | ~21,000 tokens | 文本桥接 | 需要 1M 上下文 |
| `work` | ~21,000 tokens | 文本桥接 | TraeWork 产品线 |

同一句话 `hi`：`ide` 约 0.01 积分，`remote` 约 0.15，V4-Pro 在 remote 上约 5 积分。
**换端点和换模型比抠字数有效得多。**

## 7. 排错

| 现象 | 处理 |
|---|---|
| 启动报 `Auto auth failed` | 客户端没登录，或改用 `web-login` / `manual` |
| `401 Invalid API key` | `RELAY_API_KEYS` 不匹配，或改完没重启 |
| `401 Authentication required` | 管理页要 Basic 认证，输 `.env` 里的 admin 密码 |
| `502 All upstream paths failed` | 该模型在当前端点不可用，换端点或换模型 |
| 手机上「未检测到本机授权助手」 | iOS 拦截了跨源探测，直接开 `http://127.0.0.1:8765` |
| 授权提示「X-访问太频繁」 | 上游频控，停手等 30–60 分钟，或换 PC 客户端登录 |
| 工具调用丢参数 | remote/work 的文本桥接不稳，切 ide |
| 额度掉得快 | 切 ide + 用 flash 模型 |

日志在 `logs\`：`relay.err.log`、`tunnel.log`、`helper.err.log`。

## 8. 安全

- `.env` 与 `data/accounts.json` 是**明文凭据**（JWT、refresh token），不要提交、不要同步网盘；
- 公网部署必须：`RELAY_ADMIN_USER/PASSWORD` + TLS 反代 + 只放行 `/v1/*`；
- `/v1` 只认 Bearer key，key 泄露 = 额度被刷；
- 建议只在家用内网/私有隧道里跑，不要暴露到公网搜索引擎可达的地址。
