# 安装与多账号使用说明

面向从零开始的部署。Windows 10/11，约 15 分钟。

> **2026-10-21 起支持双网关部署**：Trae2api（Trae 平台，8000）+ workbuddy2api-hub（WorkBuddy 平台，8788）。
> 两个服务互相独立，只装 Trae2api 也完全可以；需要 WorkBuddy 模型时按第 9 节加装 Hub。
> **升级上游版本前必读第 10 节**（本地补丁清单 + 防翻车流程）。

---

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| Python | 3.11 及以上（3.13 / 3.14 亦可） |
| 网络 | 能访问 `trae-api-cn.mchost.guru`、`api.trae.cn`、PyPI 镜像 |
| 账号 | 一个能正常使用 Trae 的账号（多账号见第 5 节） |
| 端口 | 8000（relay）、8765（授权助手） |

> 没有 Python 的话去 python.org 装 3.12，安装时勾选 **Add python.exe to PATH**。
> 如果你机器上有便携版 Python（例如某些软件自带的 `python.exe`），也可以直接指定。

## 2. 安装

### 2.1 取代码

把本仓库下载到任意目录，例如 `D:\trae-relay`。目录结构保持不变（`relay/`、`scripts/` 同级）。

### 2.2 装依赖

```powershell
cd D:\trae-relay\scripts
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

脚本会：

1. 找一个可用的 Python（`python` / `py -3` / 常见安装路径）；
2. 在仓库根目录建 `relay-deps\` 并安装 `relay/requirements.txt`；
3. 生成 `.env`（如果不存在）。

### 2.3 配置 `.env`

用记事本打开 `relay\.env`（没有就复制 `relay\.env.example`），最少改这四项：

```ini
TRAE_AUTH_SOURCE=auto          # auto=读本机客户端；web-login=网页授权；manual=手动 token
UPSTREAM_MODE=ide              # 推荐 ide（最省积分），需要 1M 上下文才用 remote
HOST=127.0.0.1                 # 只监听本机
RELAY_API_KEYS=sk-local-换成你自己的随机串
```

可选（强烈建议，公网访问时必须有）：

```ini
RELAY_ADMIN_USER=admin
RELAY_ADMIN_PASSWORD=换成强密码
```

> 设置了 `RELAY_ADMIN_USER/PASSWORD` 后，`/api/*`、`/web/*`、`/v1/status` 需要 HTTP Basic 认证；
> `/v1/chat/*` 仍然只认 Bearer key。

### 2.4 启动

双击 `scripts\start-all.bat`，或：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-all.ps1
```

它会拉起 relay、Cloudflare 临时隧道（可选）、授权助手，并把公网地址写到桌面 `trae-relay-url.txt`。

控制台：`http://127.0.0.1:8000/web/login`（用户名密码见 `.env`）。

> 不想开公网隧道就加 `-NoTunnel`：`.\start-all.ps1 -NoTunnel`。

### 2.5 固定公网地址（Tailscale Funnel，推荐）

默认用 Cloudflare 临时隧道，地址每次启动都会变。想要固定地址：

```powershell
# 1) 安装 Tailscale 并登录（首次会给出授权链接）
tailscale up --hostname=trae-relay

# 2) 首次开启 Funnel 需要在后台点一次开关，命令会给出链接
tailscale funnel --bg 8000
```

得到固定地址：

```
https://trae-relay.<你的 tailnet>.ts.net
```

之后 `start-all.ps1` 会自动优先使用 Funnel（检测到 `tailscale funnel status`
里有 `*.ts.net` 就不再启动 cloudflared），控制台、API、iSH 授权命令全部可以写死这个地址。

管理命令：

```powershell
tailscale funnel status            # 查看映射
tailscale funnel --https=443 off   # 关闭
```

> Funnel 是公网可达的，必须配置 `RELAY_ADMIN_USER/PASSWORD`；`/api/*` 的 Basic 认证
> 是唯一防线。

## 3. 首次登录（拿到第一个账号）

三种方式，任选：

### A. 本机 Trae 客户端（最省事，推荐）

1. 在 PC 上打开 **Trae CN 客户端**并登录；
2. `.env` 设 `TRAE_AUTH_SOURCE=auto`；
3. 重启 relay。

relay 会解密 `%APPDATA%\Trae CN\User\globalStorage\storage.json` 里的登录态，不需要网页授权，也没有频率限制。

### B. 网页授权

1. 控制台 → 账号与签到 → 「使用 Trae 网页授权登录」；
2. 本机需运行授权助手（`start-all.bat` 已自动启动，监听 8765）；
3. 浏览器登录 Trae → 授权 → 凭据自动写入。

> 手机端授权：先用 iSH 跑 `web_login.py`，再从 `http://127.0.0.1:8765` 发起。
> **不要反复点击**，上游登录接口有频率风控（"X-访问太频繁"），触发后要等 30–60 分钟。

### C. 手动填 token

控制台 → 「手动填写凭证添加账号」：

| 字段 | 来源 |
|---|---|
| Token（Cloud-IDE-JWT） | 客户端 storage.json（`scripts\dump-token.ps1` 可导出）/ 浏览器 F12 请求头 / iOS 插件 |
| Refresh Token | 登录接口响应的 `RefreshToken` 字段（可选） |
| User ID | JWT payload 里的 `data.id`（可选） |
| Client ID | 默认 `ono9krqynydwx5` |

## 4. 客户端接入

### DeepSeek Harness

设置 → 模型 → 添加模型提供商 → **自定义模型 API**：

| 字段 | 值 |
|---|---|
| Provider ID | `trae-relay` |
| API 协议 | OpenAI Chat Completions |
| API 地址 | `http://127.0.0.1:8000/v1` |
| API 密钥 | `RELAY_API_KEYS` 里的值 |
| 模型 ID | `deepseek-v4-flash`（或 `/v1/models` 里的任意 id） |

### Codex

```toml
model_provider = "trae-relay"
model = "deepseek-v4-flash"

[model_providers.trae-relay]
base_url = "http://127.0.0.1:8000/v1"
wire_api = "chat"
```

### Claude Code

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:8000
export ANTHROPIC_API_KEY=<RELAY_API_KEYS>
export ANTHROPIC_MODEL=deepseek-v4-flash
```

### 任意 OpenAI SDK

`base_url = "http://127.0.0.1:8000/v1"`，`api_key = <RELAY_API_KEYS>`。

## 5. 多账号

### 5.1 添加账号

- 网页授权：控制台点「授权登录」，每个账号登录一次；
- 手动：把另一个账号的 token 粘进手动表单；
- iOS：装插件后在手机上登录，自动复制凭据（见 `docs/越狱插件方案.md`）。

添加后账号出现在「账号与签到」列表，默认启用。

### 5.2 启用 / 停用

- 每个账号有独立的「模型请求」开关：关闭后不接收新请求，但签到、状态刷新照常；
- 全部关闭时，聊天接口返回 `503 model_account_unavailable`，不会偷偷绕回管理账号。

### 5.3 轮询

控制台「轮询与设置」：

| 模式 | 行为 |
|---|---|
| 关闭 | 只用当前选中账号 |
| 顺序轮询 | 每个新会话轮换到下一个启用账号 |
| 积分优先 | 优先用积分多的账号 |

每账号默认 2 个并发槽位（`TRAE_WEB_PARALLEL_LIMIT`），满了排队，超时返回错误。

### 5.4 切换

列表里点「切换」即把某账号设为当前默认（管理用）；轮询开启时新请求仍按轮询选号。

### 5.5 会话粘性

同一个会话（`session_id` 或历史指纹相同）会**粘住**首次使用的账号和 JWT，避免并发切号串账；
会话空闲 1 小时后释放。

### 5.6 签到

- 单账号：列表里点「签到」；
- 全部：点「一键轮询签到」；
- 定时：开启「自动签到」，设定北京时间，relay 到点自动跑；
- 遇到 `9074` 风控码会自动换设备 ID 并退避重试。

> 签到和多账号都属于规避服务条款的行为，账号风险自负。

### 5.7 账号模型开关与签到互不影响

关闭「模型请求」的账号仍会参与签到、积分查询和状态刷新，这是刻意设计。

### 5.8 多平台账号分工（双网关时）

| 平台 | 账号存在哪 | 管理入口 |
|---|---|---|
| Trae CN | Trae2api `data/accounts.json` | 控制台「账号与签到」 |
| WorkBuddy | Hub `accounts/` 目录 | Hub 看板（或 Trae2api 控制台「Hub 看板」标签） |

⚠️ 同一个 WorkBuddy 账号**不要**同时挂在两套网关上调度：两边共用同一配额，会双倍消耗且容易触发风控。一个账号只归属一套网关。

## 6. 端点与成本

| 端点 | 单次固定开销 | 工具调用 | 适用 |
|---|---|---|---|
| `ide` | ~100 tokens | 原生 tools | 默认推荐 |
| `solo` | ~100 tokens | 原生 tools | ide 异常时 |
| `remote` | ~21,000 tokens | 文本桥接 | 需要 1M 上下文 |
| `work` | ~21,000 tokens | 文本桥接 | TraeWork 产品线 |

同一句话 `hi`：`ide` 约 0.01 积分，`remote` 约 0.15，V4-Pro 在 remote 上约 5 积分。
**换端点和换模型比抠字数有效得多。**

## 7. 排错

| 现象 | 处理 |
|---|---|
| 启动报 `Auto auth failed` | 客户端没登录，或改用 `web-login` / `manual` |
| `401 Invalid API key` | `RELAY_API_KEYS` 不匹配，或改完没重启 |
| `401 Authentication required` | 管理页要 Basic 认证，输 `.env` 里的 admin 密码 |
| `502 All upstream paths failed` | 该模型在当前端点不可用，换端点或换模型 |
| 手机上「未检测到本机授权助手」 | iOS 拦截了跨源探测，直接开 `http://127.0.0.1:8765` |
| 授权提示「X-访问太频繁」 | 上游频控，停手等 30–60 分钟，或换 PC 客户端登录 |
| 工具调用丢参数 | remote/work 的文本桥接不稳，切 ide |
| 额度掉得快 | 切 ide + 用 flash 模型 |
| Hub API 返回 401 | API key 没带/被停用；Hub 鉴权开启后本机直连 8788 也要带 Bearer key |
| 控制台「Hub 看板」iframe 停在登录页 | Hub 面板密码改了但 `main.py` 里 iframe 的 `?pwd=` 没同步（见 9.3/10.3） |
| Hub 日志报 `no usable cn account` | 账号没导入或全部被停用；打开看板检查账号列表与启用状态 |
| Hub 聊天 content 为空 | `max_tokens` 太小被深度思考吃光（<32 常见）；放大到 256+ 再试 |

日志在 `logs\`：`relay.err.log`、`tunnel.log`、`helper.err.log`。

## 8. 安全

- `.env` 与 `data/accounts.json` 是**明文凭据**（JWT、refresh token），不要提交、不要同步网盘；
- Hub 的 `accounts/` 目录同理（WorkBuddy token、面板密码哈希、API key 全在里面）；
- 公网部署必须：`RELAY_ADMIN_USER/PASSWORD` + TLS 反代 + 只放行 `/v1/*`；
- Hub 若开公网入口（如 Funnel 8443）：先改掉默认面板密码 `admin`、新建 API key 并启用鉴权，缺一不可；
- `/v1` 只认 Bearer key，key 泄露 = 额度被刷；
- 建议只在家用内网/私有隧道里跑，不要暴露到公网搜索引擎可达的地址；
- 定期轮换：GitHub token、控制台密码、Hub 面板密码、两套 API key（建议 3~6 个月）。

## 9. workbuddy2api-hub 部署（WorkBuddy 模型网关，可选）

[workbuddy2api-hub](https://github.com/ardeyouxipianyi/workbuddy2api-hub) 把 WorkBuddy 账号包装成 OpenAI Chat + Responses 协议 API，自带看板、限额护栏、成长任务。纯 Python 标准库实现，任何 Python 3.10+ 都能跑。

### 9.1 获取与启动

1. 从 [releases](https://github.com/ardeyouxipianyi/workbuddy2api-hub/releases) 下载便携包（内含 `wb_proxy.py`），解压到任意目录，例如 `D:\wb2api-hub\`；
2. 启动：
   ```powershell
   cd D:\wb2api-hub
   python wb_proxy.py --host 127.0.0.1 --port 8788
   ```
3. 浏览器打开 `http://127.0.0.1:8788`（默认面板密码 `admin`，**先改掉再对外**）。

> 便携包自带的精简 Python 运行时在某些机器上会因文件 ACL 受限启动失败；确认 `wb_proxy.py` 纯标准库后，直接用本机 Python 跑即可。

### 9.2 首次配置（按顺序做）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1. 改面板密码 | 看板 → 设置 → 修改密码 | 默认 `admin` 必须换；改完全部旧会话自动失效 |
| 2. 导入账号 | 看板 → 账号导入 | 支持桌面端导出/`$wbEncrypted` 解密导入；也接受 JSON 行格式（`access_token`/`refresh_token`/`uid`/`domain`/`expires_at`，snake_case 与 cockpit 导出一致）；先勾 dryRun 预检再正式导入 |
| 3. 设默认区 | 看板设置或 `POST /realm {"realm":"cn"}` | 不设的话默认 `intl`，国内账号会打到空的国际区；设置持久化到 `accounts/active_realm.json` |
| 4. 新建 API key | 看板 → 设置 → API 密钥 | 行结构 `{id,name,key,realm,enabled}`，realm 绑 `cn`；新建后**鉴权自动开启**（无 key 一律 401，包括本机直连） |

### 9.3 与 Trae2api 控制台集成（可选）

在 `src/main.py` 控制台 HTML 加顶层标签与 iframe（本地补丁 7，见 10.4）：

- 导航栏加 `<button ... data-tab="hub" ...>Hub 看板</button>`；
- 加 `<div class="tab-page" data-page="hub">` 与 iframe；
- iframe 地址**动态判断**：本机 → `http://127.0.0.1:8788`，远程 → `https://<域名>:8443`；结尾带 `?pwd=<面板密码>` 实现免登录。

⚠️ 改了 Hub 面板密码后，必须同步 `main.py` 里 `f.src=base+'/?pwd=...'` 这一行并重启 relay，否则控制台 iframe 停在登录页。

### 9.4 远程入口（可选）

```powershell
tailscale funnel --bg --https=8443 http://127.0.0.1:8788
```

得到固定公网地址 `https://<主机名>.<tailnet>.ts.net:8443/v1`。**开 Funnel 前必须完成 9.2 的第 1、4 步**（改密码 + 启用 API key），否则等于把账号后台裸露公网。

### 9.5 开机自启（双服务）

开机脚本按「先 Hub 后 relay」的顺序写，两个块都有端口判重：

```bat
rem ---- Hub on 8788 (MUST be before relay's early exit) ----
netstat -ano | findstr /r /c:":8788 .*LISTENING" >nul 2>nul
if not errorlevel 1 goto RELAY
cd /d D:\wb2api-hub
start "wb2api-hub" /min python wb_proxy.py --host 127.0.0.1 --port 8788 >> hub.out 2>&1

:RELAY
rem ---- relay on 8000 (early exit at the end) ----
netstat -ano | findstr /r /c:":8000 .*LISTENING" >nul 2>nul
if not errorlevel 1 exit /b 0
cd /d D:\trae-relay\Trae2api-cn-main
set PYTHONPATH=D:\trae-relay\relay-deps
start "trae-relay" /min python -m uvicorn src.main:app --host 127.0.0.1 --port 8000 >> relay.out 2>&1
```

> ⚠️ 自启 bat 保持**纯 ASCII**（混入中文注释在 GBK 代码页下会被 cmd 解析炸裂）；
> ⚠️ Hub 块必须在 relay 的 `exit /b 0` **之前**。

## 10. 升级指南（防翻车，升级上游前必读）

### 10.1 升级前必做

```powershell
# 1) 备份 Trae2api 配置与数据（升级只换 src\，这两样绝不能丢）
Copy-Item .\Trae2api-cn-main\.env .\backup-env-$(Get-Date -Format yyyyMMdd).bak
Copy-Item .\Trae2api-cn-main\data .\backup-data -Recurse -Force

# 2) 备份 Hub 状态（面板密码哈希 + API key + realm + 全部账号）
Copy-Item D:\wb2api-hub\accounts D:\backup-hub-accounts -Recurse -Force
```

两套服务**不要同时升级**：先升 relay 验证，再升 Hub；谁在用谁先升，出问题另一套还能顶。

### 10.2 Trae2api 上游升级流程

1. 下载新版源码（`https://codeload.github.com/autumnsentiment/Trae2api-cn/zip/refs/heads/main`）；
2. 只替换 `src\` 目录，**保留 `.env` 和 `data\`**（`.env` 不在 src 里不会被碰，但要确认键还在）；
3. 对照 10.4 补丁清单逐项恢复（每项给了验证 grep，先查再补）；
4. 编译验证：
   ```powershell
   python -m py_compile .\Trae2api-cn-main\src\*.py
   ```
5. 重启并冒烟：`/v1/models` 模型数量正常、`/web/login` 能开、发一次真实聊天。

### 10.3 Hub 升级流程

1. 备份 `accounts\`（见 10.1）；
2. 用新 release 的 `wb_proxy.py` 覆盖（旧版重命名保留，如 `wb_proxy.py.v1.7.18.bak`）；
3. 启动并逐项验证：账号列表还在、API key 还在、默认区还是 cn、面板密码没被重置（若 settings.json 兼容，状态原样保留）；
4. 若新版本改了状态结构导致状态丢失：备份的 `accounts\` 拷回；实在不兼容就用新进程跑空目录 → 面板重新导入账号（格式见 9.2）→ 恢复 key/realm/密码；
5. 升级后跑一次真实聊天验证出字。

### 10.4 Trae2api 本地补丁清单（升级会被覆盖，逐项恢复）

| # | 文件 | 验证 grep（查到 = 补丁在） | 内容 |
|---|---|---|---|
| 1 | `src/main.py` | `admin_basic_auth` | 管理面 Basic 认证中间件 + `_ADMIN_*` 常量（原文见 10.5-A） |
| 2 | `src/sse.py` | `"auto", "auto-work"` | `_check_provider_model` 对 `auto` 提前 return，修复被上游 `__dev` 模型名误判 502（原文见 10.5-B） |
| 3 | `src/main.py` | `APP_VERSION = "1.0.6"` | 版本号修正 |
| 4 | `src/main.py` | `showHelperFallbackLink` | iOS Safari 检测不到授权助手时的兜底链接（登录页 JS，`refreshHelperDownloadLinks();` 之后插入函数 + `startAuth()` 失败分支加调用） |
| 5 | `src/main.py` | `访问太频繁` | 登录失败频控提示 |
| 6 | `.env` | （对照 10.5-D 键名） | `RELAY_ADMIN_*`、`RELAY_API_KEYS`、`TRAE_CLI_WORKDIR`、`TRAE_TASK_MODEL_ROUTING`、`TRAE_STRICT_MODEL_MATCH` |

**A. 管理面 Basic 认证（补丁 1，`src/main.py`，`auth_middleware` 之后）**

```python
# ---------------------------------------------------------------------------
# Local hardening: optional HTTP Basic authentication for the management
# surface.  The upstream project publishes every /api/* route without any
# credential check; that is not acceptable once the console is reachable from
# the public internet through a tunnel.  Enabled only when both
# RELAY_ADMIN_USER and RELAY_ADMIN_PASSWORD are set, and it deliberately does
# not cover /v1/* model traffic (those keep the Bearer RELAY_API_KEYS check).
# ---------------------------------------------------------------------------
_ADMIN_USER = os.environ.get("RELAY_ADMIN_USER", "").strip()
_ADMIN_PASSWORD = os.environ.get("RELAY_ADMIN_PASSWORD", "").strip()
_ADMIN_PROTECTED_PREFIXES = ("/api/", "/web/")
_ADMIN_PROTECTED_PATHS = {"/", "/v1/status", "/authorize"}
# The web-login helper posts credentials to this endpoint without Basic auth,
# so it has to stay reachable for the OAuth callback flow to complete.
_ADMIN_OPEN_PATHS = {"/api/web-auth"}


@app.middleware("http")
async def admin_basic_auth(request: Request, call_next):
    if not _ADMIN_USER or not _ADMIN_PASSWORD:
        return await call_next(request)
    path = request.url.path
    if path in _ADMIN_OPEN_PATHS:
        return await call_next(request)
    if path in _ADMIN_PROTECTED_PATHS or path.startswith(_ADMIN_PROTECTED_PREFIXES):
        header = request.headers.get("authorization", "")
        if header.lower().startswith("basic "):
            try:
                decoded = base64.b64decode(header[6:].strip()).decode("utf-8", "replace")
                user, _, password = decoded.partition(":")
                if secrets.compare_digest(user, _ADMIN_USER) and secrets.compare_digest(
                    password, _ADMIN_PASSWORD
                ):
                    return await call_next(request)
            except Exception:
                pass
        return Response(
            content="Authentication required",
            status_code=401,
            headers={"WWW-Authenticate": 'Basic realm="trae-relay"'},
        )
    return await call_next(request)
```

### 10.6 Git 推送备忘

- token 藏在 remote URL 里：`git remote set-url origin https://<用户>:<token>@github.com/<用户>/<仓库>.git`，推完可换回干净 URL；
- 换 token 只需重设一次 remote URL（生成新 token → set-url → push → 删旧 token）；
- 推送 502/超时多为本机代理问题：`env -u HTTP_PROXY -u HTTPS_PROXY git push`（Git Bash）或临时关系统代理。
