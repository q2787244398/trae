# Trae2api-cn 故障诊断与模型分析报告

> 生成时间：2026-10-19 17:55 ｜ 服务：Trae CN Relay v1.0.6（127.0.0.1:8000，上游 api.trae.com.cn）

---

## 一、结论先行：报错原因已查明

你截图里的错误：

> **Trae upstream error 4008: Your requests have exceeded the quota.**

**这不是你搭建的 Trae2api-cn 本身坏了**——服务本身是健康的（token 有效、5 个账号全部登录成功、5 个账号都已签到）。4008 是 **Trae 官方上游返回的"该账户积分/配额已用尽"错误**。

### 直接证据

失败记录显示，报错的 kimi-k3 请求被路由到了账号 `1853****7787`：

| 字段 | 值 |
|---|---|
| credits_before（该账号已用） | **5200.0 / 5200** |
| credits_remaining_after（剩余） | **0.0** |
| status | error（0 tokens，2.6 秒即被上游拒绝） |

也就是说：**relay 把请求轮询到了一个积分已经清零的账号上，Trae 直接拒绝并返回 4008**。

### 为什么积分烧得这么快？

今天的用量统计（截至 17:55）：

- 请求 107 次，**消耗积分 1103.81**（昨天全天只用了 7.58）
- 输入 token 高达 **470 万**，其中 deepseek-v4-pro 占 97 次请求、约 450 万输入 token

原因很典型：你在跑"分析 vboxapp 项目仓库"这类大型 Agent 任务时，**每一轮对话都会把仓库上下文重新发给模型**，单次请求输入动辄几十万 token，而 Pro 级模型（DeepSeek-V4-Pro）按 token 计费很高——实测一次 28k token 请求扣 13.35 积分（有缓存命中时仅 1.32）。几个账号就是这样被一轮轮"读仓库"烧穿的。

## 二、怎么办

1. **立即恢复**：在 relay 管理面板（`https://<你的中转域名>/web/login`）里把已耗尽的账号 `1853****7787` 暂时停用/下线，让它不再参与轮询；或把活跃账号切到还有 4504 积分的 `2609609726498537`。
2. **开启积分感知路由**：当前 `auto_route` 为关闭状态。如果面板里有"按剩余积分自动分配/剔除低积分账号"的选项，建议打开，避免再撞 4008。
3. **省积分**：
   - 大型仓库分析任务优先用 Flash/Turbo 级模型（便宜数倍），只有关键决策步骤用 Pro；
   - 缩小上下文（只喂需要的目录/文件），而不是整个仓库每轮重发；
   - 三个额度大的账号（4600/5200/1300）靠签到续命，注意每月刷新周期。

## 三、模型清单与区别

服务共暴露 **20 个真实模型**（大小写别名互为重复，实际约 17 个）+ 1 个 `auto` 自动路由。按上游通道分两组：

### A 组：remote 官方远程通道（走 trae.com.cn 官方 API）

| 模型 | 厂商 | 定位 | 积分消耗（估） |
|---|---|---|---|
| DeepSeek-V4-Pro-Official | 深度求索 | 旗舰推理，代码/复杂任务最强 | ★★★★★ 最贵（实测 28k 输入≈13 积分/次） |
| DeepSeek-V4-Flash-Official | 深度求索 | 高速平价版，日常问答/补全 | ★★ 便宜数倍 |
| deepseek-v4.1-flash | 深度求索 | Flash 迭代版 | ★★ |
| Doubao-Seed-2.1-Pro | 字节·豆包 | 通用旗舰，中文强 | ★★★★ |
| Doubao-Seed-2.1-Turbo | 字节·豆包 | Turbo 提速版，速度优先 | ★★ |

| step-5-preview | 阶跃星辰 | 预览版 | ★★★ |

### B 组：traecode 通道（走本机 solo/ide 端点，Trae IDE 内核同款）

`DeepSeek-V4-Flash`、`DeepSeek-V4-Pro`、`Doubao-Seed-2.0-Code`、`glm-5`、`glm-5-turbo`、`sagitta`、`seed-code-pro-0430` —— 这些是 Trae IDE 内部使用的模型代号，走 IDE 通道计费，通常与 A 组同源模型但走不同配额池。

### C 组：auto（fallback）

自动路由兜底，由 relay 自己挑模型。

### 积分消耗规律总结

1. **Pro/Max 级 ≫ Flash/Turbo 级**：Pro 旗舰与 Flash 轻量版差价通常在 3~10 倍；
2. **积分大头是输入 token**，且未命中缓存的输入全价计费——大上下文 Agent 任务是烧积分主力（今天 470 万输入 token 烧掉 1100 积分）；
3. **缓存命中可降一个数量级**（实测 13.35 → 1.32），同一任务连续对话比反复新建上下文便宜得多；
4. `-Official` 后缀与无后缀同名模型的区别主要是**通道不同**（remote 官方 vs traecode/IDE），模型能力基本一致，但配额池分开。
