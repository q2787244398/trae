## 2. 架构总览

```
手机/电脑客户端
   │
   ├─ Trae 模型 ─────→ Trae2api relay（8000）──→ Trae CN 官方上游
   │                    └─ 轮询 N 个 Trae 账号
   └─ WorkBuddy 模型 → workbuddy2api-hub（8788）→ WorkBuddy 官方上游
                        ├─ 调度 3 个 WB 账号（柏** / 130****9063 / 162****2136）
                        ├─ 每日 09:00 & 21:00 自动签到 + 活跃上报 + 猫猫旅行
                        ├─ 每日 22:00 Token 自动保活
                        └─ 出站身份 WB/VSC/CLI（默认 WB，见 8.2）

公网入口（Tailscale Funnel）：
  8000 → https://<你的中转域名>          （Trae API + 控制台）
  8788 → https://<你的中转域名>:8443     （Hub API，key 必带）
```

- 两个服务互相独立，一个挂了不影响另一个。
- Trae 电脑端、WorkBuddy 电脑端是**官方账号直连**，不经过中转站，无需任何配置。

## 3. 启动 / 停止 / 守护

### 3.1 启动入口（三选一，全部带 Hub）

| 入口 | 操作 | 行为 |
|---|---|---|
| 桌面「Trae Relay」快捷方式 | 双击 | 跑 `start-all.ps1`：**[0/4] 起 Hub → [1/4] 起 relay → [2/4] 公网通道 → [3/4] 授权助手**，并刷新桌面 `trae-relay-url.txt` |
| `start-all.bat` | 双击 | 同上（bat 是 ps1 的包装） |
| `start_relay.bat`（工作区根） | 双击 | 只拉两个服务（Hub 8788 → relay 8000），不碰隧道；**应急恢复用它最快** |

所有入口都有端口判重：**谁没在跑就拉谁，已在跑的秒跳过**，重复执行无害。

### 3.2 自动守护（三层）

| 层 | 机制 | 说明 |
|---|---|---|
| 开机 | 计划任务 `TraeRelayAutoStart`（SYSTEM，Boot 触发） | 跑 `start_relay.bat`，开机即起双服务 |
| 自愈 | 计划任务 `TraeRelaySelfHeal`（SYSTEM，**每 5 分钟**） | 同样跑 `start_relay.bat`；任何原因掉线（重启桌面端、进程崩溃、误杀），**最多 5 分钟自动恢复** |
| 手动 | 双击 `start_relay.bat` | 立即恢复 |

> ⚠️ `start_relay.bat` 必须保持**纯 ASCII**（中文注释在 GBK 代码页下会被 cmd 解析炸裂，踩过坑）；Hub 块必须在 relay 的 `exit /b 0` 之前。
> ⚠️ 助手会话里后台拉起的进程，会随 WorkBuddy 桌面端退出被一并清掉——所以才有自愈任务兜底。

### 3.3 停止与重启

```powershell
# 停止：双击桌面「停止 Trae Relay」（stop-all.bat），或
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop-all.ps1            # 停止
powershell -NoProfile -ExecutionPolicy Bypass -File .\stop-all.ps1 -ListOnly  # 只看状态

# 手动重启 relay（8000）——换控制台密码/换 key 后用
$p = (Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object -First 1).OwningProcess
Stop-Process -Id $p -Force
Start-Process -WindowStyle Hidden -WorkingDirectory 'C:\Users\Administrator\Documents\deepseek-harness\default-workspace\Trae2api-cn\Trae2api-cn-main' `
  'C:\Users\Administrator\AppData\Local\Programs\vbox\pyruntime\python.exe' `
  -ArgumentList '-m','uvicorn','src.main:app','--host','127.0.0.1','--port','8000','--log-level','warning'

# 手动重启 Hub（8788）——改 Hub 配置后才需要
$p = (Get-NetTCPConnection -LocalPort 8788 -State Listen | Select-Object -First 1).OwningProcess
Stop-Process -Id $p -Force
Start-Process -WindowStyle Hidden -WorkingDirectory 'C:\Users\Administrator\Documents\deepseek-harness\default-workspace\wb2api-hub\wb-proxy' `
  'C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe' `
  -ArgumentList 'wb_proxy.py','--host','127.0.0.1','--port','8788'
```

> 或直接双击 `start_relay.bat`：端口判重，谁没在跑拉谁。

### 3.4 检查更新

双击桌面「检查 Trae Relay 更新」（`check-update.bat`）。控制台本身不会自动检测更新。

## 5. 手机访问（iPhone）

### 5.1 看数据 / 改设置

手机装 Tailscale App 登录同一账号，Safari 打开 `http://100.x.x.x（Tailscale 内网IP）:8000/web/login`，输 admin 密码 → 分享 →「添加到主屏幕」。

### 5.2 新增 Trae 账号授权（iSH）

**关键机制**：Trae 授权页强制回调 `http://127.0.0.1:<port>/authorize`，所以必须在**执行授权的设备**上跑 `web_login.py`（源码注释原文如此），无法转移到服务器。

步骤：
1. App Store 装 **iSH Shell**（免费）；
2. 把下面**一整行**复制进 iSH 回车；
3. 看到 `本地监听: http://127.0.0.1:8765` 后回 Safari → 控制台 → 账号与签到 → 使用 Trae 网页授权登录；
4. 登录 → 授权 → 完成（页面卡在"登录和认证中"属正常，关掉即可）。

完整命令（密码变更后需按 10.2 节重新生成 Base64 部分）：

```
apk add --no-cache python3 ca-certificates >/dev/null 2>&1; python3 -c "import base64,urllib.request as u;r=u.Request('https://<你的中转域名>/web/login/download?as=py');r.add_header('Authorization','Basic '+base64.b64encode(b'admin:<控制台密码>').decode());open('/tmp/trae_login.py','wb').write(u.urlopen(r,timeout=30).read())" && python3 /tmp/trae_login.py
```

| 报错 | 原因 / 处理 |
|---|---|
| `HTTP Error 401` | 密码错或 `admin:` 后多了空格；换过密码必须重新生成命令（10.2） |
| SSL / 证书错误 | 先跑一次 `apk update`；命令已含 `ca-certificates` |
| 下载成功页面打不开 | 确认开的是 `http://127.0.0.1:8765` |

> ⚠️ 不要从控制台直接点「网页授权登录」：HTTPS 下 Safari 会拦截向 `http://127.0.0.1` 的探测请求，误报"未检测到助手"。**直接手动开 `http://127.0.0.1:8765` 最稳。**
> 💡 更省事：账号都在 PC 登（助手常驻），手机只用来看和切。

## 6. 上游端点与积分

### 6.1 Trae 端点怎么选（控制台「轮询与设置 → 上游端点」，改完即生效）

| 端点 | 上游 | 工具调用 | 单次固定开销 | 适用 |
|---|---|---|---|---|
| **ide**（默认） | `/api/ide/v2/llm_raw_chat` | 原生 tools，并行 | 极低 | 日常首选 |
| solo | 同上（solo_agent） | 原生 tools | 极低 | ide 异常时备选 |
| remote | `chat_sessions`（Agent） | 文本桥接 | ~2.1 万 tokens | 需要 1M 上下文 |
| work | `chat_sessions`（Work） | 文本桥接 | ~2.1 万 tokens | TraeWork |

实测（`hi`，deepseek-v4-flash）：ide 119 tokens/0.01 积分，remote 21,421 tokens/0.15 积分。**remote/work 每次带整套 Agent 系统提示，贵 10~100 倍**；1M 上下文只有 remote 支持。

### 6.2 积分规律

1. 输入 + 输出 token 总量（主因）；2. 模型档位（Pro 比 Flash 贵一个数量级）；3. **缓存命中便宜一到两个数量级**（同请求实测 13.35 vs 1.32）；4. 上游按回合结算，偶发跳变。

### 6.3 成本参考

| 组合 | 单次成本 |
|---|---|
| ide + flash | ~0.01 积分 |
| remote + flash | ~0.14~0.15 积分 |
| remote + V4-Pro | ~5 积分 |

**省积分三招：端点选 ide/solo；模型选 flash；保持同一会话吃缓存。**

## 8. 账号池管理

### 8.1 Trae 账号（控制台管理）

- 查看轮询：控制台「轮询与设置」，或 API（见 10.6 常用命令）；
- 模式：`round-robin` 顺序轮换 / **`credit-priority` 积分优先（推荐）**；
- 耗尽账号关掉「模型请求」开关即可移出候选池；
- 账号授权：PC 助手常驻自动拉起；手机用 iSH（见 5.2）。**IDE 授权的账号带 refresh_token 可自动续期；网页授权的只有 access token，失效要重新授权**——主力账号用 IDE 授权。

### 8.2 WorkBuddy 账号（Hub 看板管理）

3 个账号已全部在 Hub 调度（2026-10-21 迁入），账号增删/启停/健康检查都在看板操作（控制台「Hub 看板」标签直达）。自研池代码已删除，备份在 `default-workspace\_wb_removed_backup_20261021\`。

**出站身份（WB / VSC / CLI）**：模拟的官方客户端类型——WB=WorkBuddy 桌面端（默认）、VSC=官方 VSCode 插件、CLI=官方 CodeBuddy CLI。三条身份是**三条独立配额线**：某模型被限流（429/code 6004）时切到另一身份通常能继续用（顺序 WB → VSC → CLI，一轮最多 4 次）。看板可单账号或全池切换；「429 自动切换」默认关闭。平时用默认 WB 即可。

**签到自动化**：无需手动签到。Hub 调度器每天 **09:00 & 21:00 自动签到** + 对话活跃上报 + 猫猫旅行；**22:00** 自动刷新快过期 Token；**01:00** 跑夜猫子任务。账号页可手动补签，签到记录在「签到与活跃记录」页可查（签到成功会顺带刷新积分快照）。

⚠️ 同一个 WorkBuddy 账号**不要**同时挂在两套网关上（双端消耗同一配额且易触发风控）。

## 9. 排错

### 9.1 Trae relay 错误码

| 错误码 | 含义 | 处理 |
|---|---|---|
| **4008** | `exceeded the quota` | 账号积分耗尽。开轮询或关耗尽账号 |
| **4010** | `access denied` | 会话失效/风控。网页授权账号无法自愈，重新授权（主力账号用 IDE 授权可自愈） |
| **4011** | 账号级限流 | Trae 侧限流，稍后重试 |
| 502 | `All upstream paths failed` | 该模型在当前端点不可用；切 remote 或换模型 |
| 2001 | `failed to get app config` | raw 端点专属，个人账号无权限，别用 `UPSTREAM_MODE=raw` |

### 9.2 常见问题速查

| 现象 | 原因 / 处理 |
|---|---|
| 控制台「Hub 看板」拒绝连接 | Hub 进程没了。等自愈（≤5 分钟）或双击 `start_relay.bat` |
| Hub 看板 iframe 停在登录页 | 面板密码改了但 `main.py` iframe 的 `?pwd=` 没同步（见 10.3），改完重启 relay + Ctrl+F5 |
| Hub API 返回 401 | key 没带/被停用；本机直连 8788 也必须带 Bearer key |
| Hub 日志 `no usable cn account` | 账号没导入或全被停用；开看板检查 |
| Hub 聊天 content 为空 | max_tokens 太小被深度思考吃光；放大到 256+ |
| 手机打不开控制台 | 看桌面 `trae-relay-url.txt` 最新地址 |
| 401 Invalid API key | key 不对或 `.env` 改了没重启 |
| 401 Authentication required | 管理页 Basic 认证，输 admin 密码 |
| 工具调用丢参数/重复 | remote 的文本桥接不稳，切 **ide** |
| 额度掉得快 | 在 remote/work 上；切 ide/solo + flash 模型 |
| 账号页空白 | 没登录成功；重新授权（PC 或 iSH） |
| 重启后 `previous_response_id` 失效 | 进程内缓存，正常 |

### 9.3 网络间歇性断网（云电脑环境）

**实测结论**：是云电脑（OpenStack 虚机）的 VirtIO 虚拟网卡链路被宿主侧掐断，与本软件无关。证据：断网时 DHCP 客户端反复停/启（10-19 21:37、22:21；10-20 09:08）；Tailscale 退出比 DHCP 停止早 11 秒（被动受害者）；10-17（部署前）也断过。

已加固：Tailscale `--accept-routes=false`、关闭 WPAD、`netsh winhttp reset proxy`。断网应急：右键管理员运行 `修复网络.bat`。**不要手动绑静态 IP**（与宿主 DHCP 冲突会彻底断网）。治本：向云服务商报障（网卡 `Red Hat VirtIO Ethernet Adapter` + 断网时间点）。

## 10. 凭据轮换手册

> 建议每 3~6 个月轮换；疑似泄露立即换。换完同步更新本手册第 1 章总表。

### 10.1 GitHub token（推送 q2787244398/trae）

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token，勾 **repo**，建议 90 天；
2. 更新本机仓库：
   ```powershell
   cd C:\Users\Administrator\WorkBuddy\2026-10-19-17-09-12\trae-repo
   git remote set-url origin https://q2787244398:<新token>@github.com/q2787244398/trae.git
   git push origin
   ```
3. 可选换回干净 URL：`git remote set-url origin https://github.com/q2787244398/trae.git`；
4. 推送成功后再删旧 token。502/超时是代理抽风：`env -u HTTP_PROXY -u HTTPS_PROXY git push`。

### 10.2 控制台密码（Trae2api admin）

1. 改 `.env`：`RELAY_ADMIN_PASSWORD=<新密码>`；
2. 同步 `relay-admin-password.txt`（两处必须一致）；
3. 重启 relay（3.3）；
4. **重新生成 iSH 命令**：`[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('admin:<新密码>'))`，替换 5.2 命令里的 Base64 部分；
5. 同步本手册 1.2 总表。

### 10.3 Hub 面板密码

1. 看板 → 设置 → 修改密码；或 API：`POST http://127.0.0.1:8788/panel/password`，body `{"current":"旧","new":"新"}`（改完旧会话全部失效）；
2. **同步控制台 iframe**：改 `Trae2api-cn-main\src\main.py` 约 2395 行 `f.src=base+'/?pwd=<新密码>';` → 重启 relay → Ctrl+F5；
3. 密码哈希在 `wb2api-hub\wb-proxy\accounts\settings.json`（salt+PBKDF2 不落明文）；备份 `accounts\` 即备份密码与 key。

### 10.4 Hub API key（`wbhub-...`）

1. 看板 → 设置 → API 密钥：先**新增**新行（realm=cn、启用）→ 客户端全切新 key → 再停用旧行（无缝轮换）；
2. 手机 App 的 key、本机脚本同步换；更新本手册 1.2。

### 10.5 Trae relay API key（`sk-dsh-...` / `sk-local-...`）

1. 改 `.env` 的 `RELAY_API_KEYS`（逗号分隔）：先追加新 key → 重启 → 客户端全切 → 再删旧 key → 再重启；
2. 同步 `relay-api-key.txt` / `relay-dsh-key.txt` 与本手册 1.2。

### 10.6 常用管理命令

## 12. 本地补丁与升级方法

Trae2api 是上游 v1.0.6 的**本地改造版，共 8 处改动**，升级上游会被覆盖，必须重新打（仓库 `docs/安装与多账号说明.md` 第 10 节有完整流程与补丁原文）。

### 12.1 补丁清单

| # | 文件 | 验证 grep（查到=补丁在） | 内容 |
|---|---|---|---|
| 1 | `src/main.py` | `admin_basic_auth` | 管理面 Basic 认证中间件 + `_ADMIN_*` 常量 |
| 2 | `src/sse.py` | `"auto", "auto-work"` | `_check_provider_model` 对 `auto` 提前 return（修复被 `__dev` 模型名误判 502） |
| 3 | `src/main.py` | `APP_VERSION = "1.0.6"` | 版本号修正 |
| 4 | `src/main.py` | `showHelperFallbackLink` | iOS Safari 检测不到授权助手时的兜底链接 |
| 5 | `src/main.py` | `访问太频繁` | 登录失败频控提示 |
| 6 | `.env` | （对照下方模板键名） | `RELAY_ADMIN_*`、`RELAY_API_KEYS`、`TRAE_CLI_WORKDIR` 等 |
| 7 | `src/main.py` | `data-tab="hub"` | 控制台顶层「Hub 看板」标签 + iframe 动态地址（`?pwd=` 指向 Hub 面板密码，约 1989/2395 行） |
| 8 | `src/main.py` | `_tag_model_platform` | 模型目录分类字段：`_pretty_model_name` / `_tag_model_platform` / `groups`（`/v1/models` 附带 platform/display_name/groups，纯附加） |

### 12.2 升级步骤

1. **备份**：`.env`、`data\`、当前 `src\main.py` 与 `src\sse.py`（留档对照）；
2. 下载新版：`https://codeload.github.com/autumnsentiment/Trae2api-cn/zip/refs/heads/main`，**只替换 `src\`**（`.env` 与 `data\` 不动）；
3. 检查补丁丢失：
   ```powershell
   Select-String -Path .\src\main.py -Pattern 'admin_basic_auth','showHelperFallbackLink','APP_VERSION = "1.0.6"','data-tab="hub"','_tag_model_platform'
   Select-String -Path .\src\sse.py -Pattern '"auto", "auto-work"'
   ```
4. 按 12.1 逐项恢复（补丁原文见仓库文档 10.5）；
5. 编译验证：`python -m py_compile .\src\*.py` → 重启 → 冒烟（模型数、控制台、真实聊天）。

> 一句话：**会丢的是 `src\` 里的 7 处代码补丁（1~5、7、8）；`.env` 和 `data\` 只要不删就不丢。**
> Hub 升级另见仓库文档 10.3（备份 `accounts\` → 覆盖 `wb_proxy.py` → 验证账号/key/realm/密码都在）。

## 13. 安全提醒

- 控制台暴露在公网隧道，靠 Basic 认证保护；**拿到 admin 密码 = 可改上游、删账号、看消费**；
- Hub 公网 8443 靠 **API key（API）+ 面板密码（看板）** 双重保护；改密后同步控制台 iframe（10.3）；
- `/v1` 只认 API key，**key 泄露 = 积分被刷**；
- `.env`、`data\accounts.json`、Hub 的 `accounts\` 全是明文凭据/哈希：不同步网盘、不进仓库；
- 自动化、多账号轮询属于规避 Trae/WorkBuddy 服务条款，有封号风险，自用低调；
- GitHub token、各密码、各 key 定期轮换（第 10 章）。
